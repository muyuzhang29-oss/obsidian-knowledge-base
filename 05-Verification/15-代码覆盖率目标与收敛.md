# 15-代码覆盖率目标与收敛

> [!abstract] 与功能覆盖率的分工
> - **代码覆盖率**：工具自动统计「RTL 哪些代码/条件/状态被执行」——**不完成功能正确**
> - **功能覆盖率**：你写的 coverpoint 是否测到规格场景
>
> 两者都要；本篇讲**代码覆盖怎么定目标、怎么看、怎么收敛**。

---

## 1. 六大类代码覆盖率

```text
Code Coverage
├── Line      行/语句
├── Toggle    信号 0↔1
├── Branch    if/case 两个方向
├── Condition 复合条件原子真值
├── FSM       状态/迁移
└── Path      路径覆盖（易爆炸）
```

| 类型 | 强项 | 典型目标 |
|------|------|----------|
| Line | 死代码、漏编译 | 100% 或剔除死代码 |
| Toggle | 总线/控制脚是否翻过 | 关键接口 100% |
| Branch | 漏分支 | 与 Line 一起看 |
| Condition | 漏条件组合 | 关键控制逻辑 |
| FSM | 状态机可达 | **每个状态 + 迁移** |
| Path | 路径组合 | 只给核心状态机，慎用 |

---

## 2. 目标怎么定（别死磕 100%）

> [!tip] 行业常见 sign-off 口径
>
> | 模块 | Line/Cond/Branch | Toggle | FSM |
> |------|------------------|--------|-----|
> | 标准 IP | 95%+ | 关键接口 100% | 100% 状态 |
> | 复杂控制 | 90%+ | 90% | 100% 状态 |
> | 存储宏 | 剔除后统计 | — | — |

**必须人工剔除（exclude）：**

- 综合/DFT 逻辑、`ifdef` 死分支
- 断言绑定、验证专用逻辑
- 不可达状态（设计保证）
- 工具宏、自动 generated wrapper

---

## 3. Toggle：接口脚优先

```systemverilog
// 只关心接口与关键控制
covergroup cg_toggle @(posedge clk);
  coverpoint apb.psel   { bins neg2pos = (0=>1); bins pos2neg = (1=>0); }
  coverpoint apb.penable { bins x = (0=>1=>0); }
endgroup
```

> [!warning] 整片都追 Toggle 会失败
> 内部寄存器位很多设计上就不会翻，应 **exclusion 文件** 管理，不要改 RTL 硬凑。

## 4. FSM 覆盖率

```systemverilog
// 显式 covergroup 与工具 FSM 报告互补
covergroup cg_fsm @(posedge clk);
  coverpoint state {
    bins idle  = {ST_IDLE};
    bins work  = {ST_RUN, ST_DONE};
    illegal ill = {ST_X}; // 不可达
  }
  coverpoint transition {
    bins i2r = (ST_IDLE => ST_RUN);
    bins r2d = (ST_RUN => ST_DONE);
    bins d2i = (ST_DONE => ST_IDLE);
  }
endgroup
```

- **状态**：每个编码至少命中一次
- **迁移**：设计保证可达的迁移都要测
- 用 `illegal bins` 标不可达，工具会报违例

---

## 5. Condition 与表达式

```verilog
assign valid = en && !busy && (len != 0);
// 需要 en/busy/len 组合，不是只测 valid
```

```systemverilog
coverpoint en   { bins z={0}; bins o={1}; }
coverpoint busy { bins z={0}; bins o={1}; }
cross en, busy;
```

## 6. 收敛流程（实战）

```text
1) 回归跑满 baseline → 导出 code coverage 报告
2) 工具标 Top uncovered：
   - Line/Cond 未覆盖行
   - Toggle 未翻位
   - FSM 未达状态/迁移
3) 分类：
   a) 死代码 / 不可达 → 建 exclusion（写理由）
   b) 漏激励 → 补 sequence / 约束
   c) 漏检查 → 覆盖率到了但没 pass → 查 scoreboard
4) 重跑单测钉住 → 再全量回归
5) 差距率 < 目标 → 出 exclusion 清单 + 覆盖率签字
```

> [!bug] 常见坑
> - 覆盖率高但 **功能覆盖点** 没设计 → 假收敛
> - 只看百分比、不看 **uncovered 清单**
> - path coverage 不关掉会指数爆炸
> - 增量仿真只加不减，累积死代码没人清

---

## 7. 报告怎么读

| 报告项 | 动作 |
|--------|------|
| 未覆盖 Line | 看是否 `else if` 末级、死分支 |
| 未翻 Toggle | 对照接口是否在测试里驱动过 |
| FSM 未达 | 加复位/错误恢复场景 |
| 覆盖率骤降 | 新代码未测 or 用例被禁用 |

---

## 8. 与功能覆盖的联表

| 场景 | 代码覆盖 | 功能覆盖 | 结论 |
|------|----------|----------|------|
| 写配置可读回 | ✓ | ✗ | 不充分 |
| 写配置可读回 + 异常值 | ✓ | ✓ | 可接受 |
| 覆盖率 95% 但错误注入无 coverpoint | 高 | 低 | **不收敛** |
